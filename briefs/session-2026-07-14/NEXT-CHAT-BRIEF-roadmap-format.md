## THE CORE QUESTION
**Is Now / Next / Later the right roadmap format for the user journey we are building?**

It has never been decided. It is an unexamined assumption threaded through the pipeline, the mockups,
and the sequencing bug (F34). Before Phase 2 builds 16 screens around it, we should know if it's right.

## What to actually think about (do not just default to a framework)
- **What is the roadmap FOR, for a solo/non-technical founder?** Time horizons (Now/Next/Later)?
  Priority order? Themes-with-tasks-underneath? A single "do this next" and everything else deferred?
- Now/Next/Later is a TIME-HORIZON frame. Is "when" the axis a lone founder needs — or is it
  "what matters most" / "what's the one thing"? A founder with no team may not think in quarters.
- **How does this interact with the human-in-the-loop decision?** If the founder confirms themes
  via questions, does the OUTPUT structure change? The format and the elicitation are coupled.
- **Themes vs tasks:** the spike is testing whether users even want themes, or want a checklist.
  The answer directly determines the format. Don't settle format before that signal is in — but
  DO map the options.
- **What does the "spectacular reveal" (a stated product goal) actually reveal?** The format IS
  what gets revealed. A weak format = a weak reveal, however good the motion.
- Consider real alternatives, not just Now/Next/Later: a single prioritised list; one hero action +
  a deferred pile; themes as headers with a first task each; a "critical path" sequence; horizon
  columns. Weigh each against the solo-founder journey.

## Constraints to respect (from this session — do not reopen)
- **Human-in-the-loop is decided.** The pipeline proposes; the founder confirms. Design within that.
- **Dates are derived from sequence, never model-generated** (N7). Whatever format, ordering must be
  deterministic.
- **"Only show if earned"** — nothing padded to look complete. A one-theme roadmap is legitimate.
- **Themes count 1–3, never hardcoded.**
