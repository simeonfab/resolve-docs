## Standing rules
1. **Pixel-exact.** Every colour, spacing value, font, radius, and copy string in the referenced mockup is the spec. No new styles, even "improvements."
2. **Bizarro Superman rule.** If an instruction isn't specific enough to build without guessing, that's a failure of the ticket, not permission to guess. Stop and ask.
3. **Never invent data.** Mockup content is fictional placeholder ("Nook & Thread rebrand"). Real data comes from `projects`, `project_sessions`, `initiatives`, `work_items`. Never hardcode example content.
4. **File-touch audit before parallelising.** Before running two "parallel-safe" tickets, list which files each touches. Overlap → run sequentially.
5. **Real production verification.** A ticket is not done until checked against the live deployment with real data — the Chunks 01–03 standard.
6. **Report deviations and ambiguity explicitly.** Never silently resolve something you're unsure about.
7. **Only show if earned.** Never pad UI or outputs to look complete — applies to reports, roadmaps, and risk sections equally.

## Workflow
- **Branch-first:** build on a branch → verify on Vercel preview against real data → merge to production.
- **Commit early and often.** Uncommitted work is unrecoverable on container reset.
- **Walking skeleton first:** thinnest connected end-to-end version before depth.
- No screen build starts without its mockup.

## Data-reality rules (non-negotiable — born from a real failure, see Mistakes log #1)
1. Fixtures must be generated by the real pipeline — never hand-written.
2. Before building any screen, run a data-reality check: query a real, non-fixture project and confirm the fields the screen needs actually exist and hold sane values.
3. Final verification happens on a real project, not fixtures.
4. Semantic derivations (deriving meaning from data) get flagged for review — never self-verified.
5. An upstream gap that has been logged is **blocking**, not a note. Stop and raise it.

## Mistakes log — append-only
Read before starting work. Format: what happened → rule that prevents it.

1. **Fixture masking.** Hand-written fixtures masked a total pipeline failure — screens looked correct while the real pipeline produced garbage. → The five data-reality rules above; verification always on a real, non-fixture project.
2. **theme_index bug.** Roadmap generation wrote wrong theme names into some work items via a bad index. → When mapping across collections, verify the join key against real rows, not assumed ordering.
3. **Uncommitted work lost.** A container reset destroyed uncommitted session work. → Commit early and often within every session; never let verified work sit uncommitted.
