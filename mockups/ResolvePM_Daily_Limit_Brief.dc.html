01 · THE MODEL

A fourth sibling, not an error

This is the same screen slot as the narrated progress checklist on /roadmap — a sibling of pending / stalled / failed. It reuses their skeleton and amber logic, but reads calm, not alarming. It is not an error state and must never look like one.

  • The daily generation capacity is reached. Nothing is lost — the project, context and any work done so far are saved; generation resumes automatically the next day.
  • There is no working retry, and dead controls are banned. The state carries one live control: a real "Back to your dashboard" navigation. No disabled button, no countdown, no "try again".
  • The processing ring is complete and still (a slow opacity breathe, no rotation). Rotation reads as "working now", and it isn't.
Copy ships as written. Every string in §3 is final. Do not paraphrase in code — the honest-but-warm wording is the deliverable.

02 · WHICH VARIANT FIRES

One branch, on milestones completed

Same state, same slot, same control. The only branch is how much work was banked before the limit was hit:

milestonesDone === 0

State 1 — pure reassurance

Nothing started today. Settled ring + "what happens next" card. No checklist.

milestonesDone ≥ 1

State 2 — progress acknowledged ★

Paused mid-way. Reuse the pending checklist, frozen: ticked rows stay amber, unreached rows fall back to dashed "awaiting" cards.

Never show an empty checklist. At zero milestones there is nothing to acknowledge — fall back to State 1. State 2 is the recommended default whenever real progress exists.

05 · MOTION

Quick, and honestly still

ElementMotion
Enteropacity 0→1 + 6px rise on headline, ring and card, staggered 60ms, ~200ms ease, fill:both
Ringholds a 3.2s opacity breathe at 0.85→1 · no rotation · full amber stroke, filled centre dot
Ticked rowsdo not re-animate — they were already ticked in the pending state; State 2 inherits them mid-flight
Reduced motion (prefers-reduced-motion): drop the breathe (ring held at full opacity), enter becomes a single <120ms opacity fade — no translate, no stagger. Copy and layout identical; no second design to maintain.

06 · BANNED HERE

Non-negotiable — reject in review

  • No dead controls: no disabled buttons, no "retry" / "try again".
  • No countdown timers or "resumes in 6h 12m".
  • No counters: "X generations remaining" appears nowhere in the product.
  • No system vocabulary: quota · rate limit · API · tokens · capacity pool.
  • No error tone: no red, warning triangles, apology or blame.
  • No upsell: nothing implying payment or upgrading removes the limit.

07 · OPEN DECISIONS TO LOCK

Confirm before ticketing

  • 1State 2 trigger source. What signals milestonesDone at the moment the limit is hit — the same progress feed the pending checklist ticks on? Recommend: reuse that feed; snapshot its last-completed index.
  • 2Where "Back to your dashboard" lands. The cockpit home with the saved project + first move already present. Confirm the route.
  • 3Surface 2 in scope? Ship the bridge notice (2A) + post-signup screen (2B), or defer and land everyone on State 1? Recommend: ship — it's the cheaper, higher-trust moment to say it.
  • 4Auto-return on the next day. When generation resumes and finishes overnight, does this screen live-swap to the reveal, or is it picked up on next open? Confirm so the "waiting on this screen" copy stays true.
