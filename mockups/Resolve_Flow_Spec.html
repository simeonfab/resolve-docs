SURFACE BBridge transition repo: Intake

Container = single dark stage (background:var(--ink)). Total loop 9200ms, 4 beats via 4 absolutely-stacked layers (position:absolute; inset:0; flex-center), each running its own @keyframes … 9200ms infinite. Stays on Ink + Amber throughout — no dark→light shift mid-bridge. A shared amber glow pulses under all beats.

B1 · Beat 1 — “You just cleared the fog” 0.0–2.3s

The trophy card already on the final screen (.growcard: dark bg, 1px solid rgba(200,160,64,.28), radius 16, shadow) grows in one continuous smooth zoom to take over the screen. Not a cut to a fresh fog screen. Must not step or jutter.

Key rule

Do not subdivide the growth into small scale steps — uneven per-segment velocity was the original jutter cause. Keep 8%→25% as a single segment.

B2 · Beat 2 — First move 2.4–4.5s

Amber-check chip showing the user’s real next task — bind to the live value, never hardcode (example: “Finalize the brand name selection”) — with caption “Bringing your first move with you.”

B3 · Beat 3 — Workspace forming 4.6–6.6s

Resolve mark (44px amber tile “R” + wordmark) and 3 context chips fan in; caption “Setting up your workspace.”

B4 · Beat 4 — Sign-in 6.8s → holds

Renders the canonical sign-in minimal state (Surface C): brandmark top-centre, DM Serif headline “Create your Resolve workspace”, field placeholder “Your email” with amber focus ring, “Send code” button. No eyebrow / subhead / footer shown. Must be pixel-identical to R1’s first frame.

SURFACE EDashboard motion repo: ResolvePM

Every animation on the home Dashboard, in trigger order. All values are literal and locked to the “match-seam” character — spring on arrivals/expansions, calm ease on fades/dims. Implement with WAAPI (element.animate(keyframes, options), fill:'both') or the equivalent CSS @keyframes; staggered steps apply delay + (index × stagger) per element in DOM order. Reference file: ResolvePM Dashboard Motion.dc.html.

Easing tokens (dashboard)

--e-springcubic-bezier(.34,1.56,.64,1) — arrivals, expansions, sheets (slight overshoot)
--e-outcubic-bezier(.22,.61,.36,1) — decelerate-in reveals, restore
--e-stdcubic-bezier(.4,0,.2,1) — dims, press, tab color
--e-incubic-bezier(.55,0,.85,.35) — exits / route-out

E1 · Screen entrance on land / tab return

Fires once when the Dashboard mounts. Three steps on one clock.

E2 · Blocked card → expand tap “Waiting on” card

E3 · Expand → collapse tap backdrop / dismiss

E4 · Global bar → agent chat tap the global bar

E5 · Win card idle + tap route-out

Idle loop

The route arrow drifts +3px on 2.6s ease-in-out infinite (translateX 0 → 3px → 0) — always running, independent of tap.

E6 · Pointer card → route out tap “Worth a look”

E7 · Profile menu open tap avatar (top-right)

Menu anchors to the avatar: transform-origin: top right, so it unfolds downward from its own corner. Tapping the backdrop reverses it (fade 160ms).

E8 · Switch tab tap another bottom-bar tab

Directional: outgoing content exits toward the previous tab, incoming enters from the opposite side. Same recipe for any tab pair — flip the sign for backward navigation.

SURFACE FRoadmap tab motion repo: ResolvePM

Every animation on the Roadmap tab, plus the onboarding hand-off. Same easing tokens and “match-seam” character as the Dashboard (Surface E). WAAPI, fill:'both'; staggered steps apply delay + (index × stagger) in DOM order. Reference file: ResolvePM Roadmap Motion.dc.html.

Navigation decision

The onboarding “whole picture” matrix is not a sixth bottom-tab or a third toggle segment — it is the same data as By theme with an extra axis. It lives as a pull-up overlay (grid icon beside the By phase / By theme toggle), so the five tabs and two views stay clean. See F5.

F1 · Screen entrance on arrival / tab-in

The receiving end of the Dashboard’s tab-switch (Surface E8). Header → title → toggle → phase groups → global bar.

F2 · View toggle — By phase ⇄ By theme tap the segmented control

Directional: switching right (to By theme) sends the outgoing view left and brings the incoming from the right; reverse for the other direction. The thumb leads on a spring; content swaps at the midpoint.

F3 · Action card → expand inline tap a Now / Next / Later card

Expands in place and pushes the cards below down — no modal. Reveals a context line + a Go to work item button. Only one card open at a time; tapping another collapses the first.

F4 · Action card → collapse tap the open card again / another card

F5 · Open the “whole picture” matrix tap the grid icon by the toggle

Reuses the onboarding reveal — the same theme × Now/Next/Later grid — as a full-screen overlay. A zoom-out you pull up and dismiss (× or backdrop).

F6 · Onboarding → tab (slide away)

Source

Fires on the “Open my roadmap” button of ResolvePM Roadmap Reveal.dc.html (the “Here’s the whole picture” grid). That grid is mounted as the overlay on top of the finished Roadmap tab; the button plays this, then lands on the tab.

The simplest clean transition. The matrix is a full-screen layer sitting on top of the already-composed Roadmap tab; on tap it slides straight down and off, revealing the tab that was there all along. One transform on one element — the tab underneath never animates, so there is no crossfade muddiness and nothing to measure.

SURFACE GWork tab motion repo: ResolvePM

Every animation on the Work tab — a checklist grouped into Now / Waiting on / Captured inbox / Upcoming / Synced. Same easing tokens and match-seam character as Surfaces E–F. WAAPI, fill:'both'. Reference file: ResolvePM Work Motion.dc.html.

Interaction model — read first

A task row has two targets. The tick (the circle) is the ONLY thing that completes an item (G2). Tapping the row body opens the item for editing (G3) — it never completes it. Wire the tick’s handler with stopPropagation so it doesn’t also trigger the row.

G1 · Screen entrance on arrival / tab-in

G2 · Task check-off tap the tick only

The completed row leaves the list; the item is then retrievable in Completed (G5). One task ≈ 8% of the bar (1 of 12).

G3 · Open a work item (edit) tap the row body

Opens the item for editing rather than completing it — a detail screen pushes in from the right (forward nav): editable Title, Theme, an End date field, Notes, with Save + Mark complete. “Mark complete” closes the editor, then runs G2 on that item. Back slides it off right.

G4 · Capture → inbox type into the global bar

G5 · View completed work tap “N done this week ›” on the progress row

Completed items collect here — a light view onto what actually lives in the Knowledge base (footer “View all in Knowledge” jumps to the Knowledge tab). Grouped This week / Earlier. Same push mechanic as G3.

G6 · Global bar → agent chat reused

Reuse E4

Identical motion to the Dashboard’s global bar → agent chat (Surface E4): backdrop dim, sheet rises from the bottom (spring), content fades in staggered. Only the resting caption differs — here “Add a task, or ask what's next.” Do not re-implement.

SURFACE HKnowledge / Library motion repo: ResolvePM

The Knowledge tab is intentionally not shaped like the list tabs — it’s a library/repository you both read from and add to (files, notes, brain-dumps), and the home for completed work + intake knowledge. Search, filter chips, a two-column typed-card grid. Same easing tokens as E–G. Reference file: ResolvePM Knowledge Motion.dc.html.

Not read-only

Users add here (Write a note / Attach a file / Paste text) — the library is a dumping ground as well as a reference. Cards carry a type badge: Intake · Done (completed work) · Files · Notes. The old “Recommended action” card is removed (no distinct tap value).

H1 · Screen entrance (library reveal) on arrival / tab-in

Deliberately grid-y, not a feed, so it reads as opening a repository.

H2 · Filter the library tap a chip — All / Intake / Completed / Files / Notes

H3 · Add / brain-dump tap the “Drop a file…” tile, ＋, or the global bar

A bottom sheet offers Write a note / Attach a file / Paste text; choosing one drops a fresh card into the top of the grid.

H4 · Open an item → preview tap any card

Document/preview screen pushes in from the right with a Download action — same push mechanic as the Work editor/completed screens (G3/G5).

H5 · Global bar → agent chat reused

Reuse E4

Same motion as Dashboard E4; caption “Add to your library, or ask about your project.” The bar does double duty here — ask, or open the add sheet (H3). Do not re-implement.

SURFACE IFeedback — confirmations & undo repo: ResolvePM

Cross-cutting toast system. One toast at a time, seated just above the global bar; a new action fast-swaps the current one (160ms out, then in). Same easing tokens. Reference file: ResolvePM Feedback Motion.dc.html.

When to use which

Reversible / destructive-ish actions (complete a task, delete, archive) → toast WITH Undo + a 4s depleting timer bar (I1). Non-reversible / low-stakes (Send reminder, Save) → shorter plain toast, no timer, no Undo (I3). DEV: cancel any pending follow-through (e.g. the check-off’s row-collapse timer) when Undo fires, or the action completes anyway after dismissal.

I1 · Confirmation toast + undo reversible action (e.g. task complete)

I2 · Undo (reverse) tap Undo before the timer lapses

I3 · Plain confirmation Send reminder · Save · non-reversible
