A · INTAKE

Bridge re-timed to ≤5s

The old bridge held four narrated beats at ~2s each (8.2s total, final beat held-until-ready). The cap is now ≤5s. Beat 2 (the first-move pin) merges into beat 1's trophy zoom — the first move surfaces during the zoom, not as a separate held beat. Workspace-forming compresses. The park beat is unchanged and still holds-until-ready.

New timingBeatChange
0.0–2.0sTrophy zoom + first moveBeats 1 & 2 2.3s + 2.1s merged into one 2.0s move. The pin rides the zoom instead of waiting its turn.
2.0–3.4sWorkspace formsBeat 3 2.0s → 1.4s. Same mark + context-chip fan, tighter 40ms stagger.
3.4–4.6s → holdPark / arrivalUnchanged. Byte-for-byte R1's first frame; holds-until-ready; redirect fires while it holds.

A · bridge captions (final)

beat 1 captionBringing your first move with you
beat 2 captionSetting up your workspace
beat 3 (park)— no caption; the mark rests and the glow settles into the real screen —
Arrival preserved. Amber is the through-line across all three beats and into the park glow, so the seam still reads as arrival. The 4.6s is a floor: fast backends redirect at 4.6s, slow ones simply hold the park frame — the only motion left is the settled glow breathe, so nothing ever stalls mid-move. Reduced motion: zoom + stagger become a <120ms cross-fade between beats; total still ≤5s.

B · HOUSE-WIDE

Loader overrun — one pattern for every narrated loader

No loader defines what happens when the real wait outlasts its narrated loop; checklists just stall on the last tick. This is the generic treatment, specced against the intake "Reading your project" loader but written to drop onto any of them (Weighing, cockpit milestones).

ThresholdBehaviour
Loop end (~5s)Last checklist row is active, not pre-ticked. If work is done, reveal fires.
+8s past loopSoften to overrun: swap headline + subline, ring keeps spinning, indeterminate shimmer replaces finished progress. Loops indefinitely.
45s absoluteHand to the existing failed sibling: ring still + terracotta, honest fault copy, real retry.

B · overrun copy (final) — specced on "Reading your project"

overrun headlineStill on it.
overrun sublineTaking a little longer — your project has more in it than most. Nothing's stuck.
last checklist row (gains qualifier)Shaping your path — carefully
failure headline (boundary)This one didn't go through.
failure sublineSomething on our side got stuck — not your project. It's all still saved.
failure controlTry this again →
Drop-in for any loader. Only two strings change per loader — the overrun headline and subline. Shimmer, thresholds and the failure hand-off are shared. Cockpit milestone loaders inherit it unchanged.
Banned in overrun: countdowns or "~30s remaining"; a spinner that stops before the failure boundary (reads as frozen); apology tone before 45s; blaming the user's input for the wait.

C · COCKPIT — THE LARGEST LANE

cap-pm-cockpit-alaria · Work tab + item drawer

The work loop, made whole

Six patterns, all extensions of the existing drawer + Work-row language. The mockup's phone runs the whole loop live.

1 · Create affordance + create sheet

Entry from two places: a quiet New task text button in the Now section header, and the global input bar. Opens a bottom sheet — title required, description + due date optional. Submits straight into Now.

C1 · create sheet (final)

section-header buttonNew task
sheet titleNew task
title fieldTitle · placeholder: "What needs doing?"
description fieldDescription · optional · placeholder: "Any detail worth keeping"
date fieldDue date · optional · "Add a due date"
primary / cancelAdd to Now · Cancel

2 · Date picker (in-drawer, clearable)

Custom month grid inside the sheet/drawer — today marked, selected day amber, a Clear control once set. Rule: the platform-native <input type=date> is an acceptable fallback on mobile if styled to the surface, but the custom grid is the drawer-consistent default so the picker matches the rest of the drawer language.

3 · Date chip on rows + overdue

Due date renders as a quiet chip in the row meta, beside the theme tag. Overdue is a distinct but calm variant — terracotta ink, a small dot, the word "overdue" spelled out. Overdue is information, not shame.

Overdue is not alarming: no red, no warning triangle, no icon-alarm. Same chip shape, terracotta ink + dot, "· overdue" appended. It informs; it does not scold.

4 · Complete affordance + just-completed behaviour

Fast path: tap the circle on the row — no drawer needed. The completed row shows a ~700ms settle (checkmark fills, row fades to ~0.5 opacity) then drops into the Done section. Long enough to feel earned, short enough not to block the next tick.

5 · Delete confirm + undo toast

Soft delete. Delete is a drawer action (and an inline row confirm); on confirm the row leaves and a ~5s undo toast appears with a draining amber bar. Undo restores the item in place. Nothing is hard-deleted until the toast expires.

C5 · delete + undo (final)

inline confirm promptDelete this task?
confirm buttonsKeep · Delete
undo toastDeleted "[task title]" · Undo

6 · Done-item visibility

Completed items live in a collapsed Done section at the foot of the Now list, showing a count ("N banked"). Expandable to review or un-complete. Completing feels like banking progress, not deletion — the count going up is the reward.

"Banked", not "done and gone". The count is deliberate: it makes completion visible as accumulation. Un-completing from the Done section returns the row to Now.

D · FIRST-RUN SHELL

Dormant nav state

During first-run only Roadmap is live. The other four render dormant — ghosted mark + a quiet label bar, ~32% opacity, slightly desaturated, not tappable. They don't vanish (that would hide where the app is going); they read as "coming", never "broken". They come alive as part of the arrival reveal.

ElementTreatment
Dormant tabGhosted icon at ~32% opacity + slight desaturation; label collapses to a quiet bar (no text). Non-interactive.
Roadmap tabFull amber, live, the only tappable surface.
Wake (arrival)Four tabs fade ghost→full and rise 3px, staggered 100ms left-to-right; labels resolve bar→text in the same beat.
Reduced motion: the wake becomes a single <120ms cross-fade — no stagger, no rise. The dormant and live end-states are identical to the animated path.

E · ROADMAP "WHOLE PICTURE"

Theme-rail text treatment

The vertical theme rail on the roadmap grid is only ~64px wide, so long titles fragment mid-word (one syllable per line) and tall rails shove the grid down. Acceptance: no title broken mid-word or cut off, at 390 or desktop, up to ~60 characters.

OptionTreatment
E1Today — fragmented. The bug: 64px rail, break-all wrapping.
E2Rotated rail (40px): text 90°, single line, never breaks. Buys most grid width; reading sideways is slower.
E3 ★Recommended. Rail widens to 130px; titles wrap on word boundaries, clamp to 2 lines; overflow truncates with full title on tap/hover (reuse the existing provisional-tooltip affordance).
Why E3. Keeps horizontal reading (fastest), never breaks a word (word-break stays normal), reuses the existing tooltip for overflow — no new affordance. Acceptance: "Reposition for a higher price point" (35 ch) wraps to 2 clean lines; a synthetic 60-char title clamps + ellipsis with full text on tap; no mid-word break at 390 or desktop. E2 is the drop-in alternate if a dense portfolio view needs maximum grid width.

OPEN DECISIONS TO LOCK

Confirm before ticketing

  • ABridge floor vs. cap. Is 4.6s acceptable as the floor, or must fast paths land closer to a hard 3s? Recommend: 4.6s floor — it preserves the three-beat arrival read.
  • BOverrun thresholds. Confirm N = 8s past loop and the 45s absolute ceiling, or set per-loader values with eng. Recommend: ship the house defaults, override per loader only where the backend p95 demands it.
  • CDate picker: custom vs. native. Ship the custom in-drawer grid everywhere, or allow styled native date input on mobile? Recommend: custom grid as default; native accepted where the drawer can't host the grid.
  • CCompleted-item retention. Does Done keep everything for the week, or roll off after N days? Confirm so the "N banked" count stays meaningful.
  • DDormant tap behaviour. Fully inert, or a one-line "arriving with your dashboard" toast on tap? Recommend: inert — the ghost state already says it.
  • ERail treatment. Lock E3 (wider rail) as default, E2 (rotated) reserved for dense views?
