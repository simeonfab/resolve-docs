01 · THE FRAME

What the dashboard is for

The remaining gap is content, not spacing — the density pass (T5) already shipped. Design to one job:

  • Orient the founder in ~5 seconds and point them at their single highest-value next move. The "good morning, here's what matters today" surface.
  • It is not a full analytics view and not a second roadmap. The Roadmap tab owns the plan; the dashboard owns today.
  • The anchor is settled: the hero is the highest-value activity = the first task of the roadmap's focus theme, live — it advances as work completes. Everything else supports it; nothing rivals it for prominence.

02 · THE RECOMMENDATION — (a) vs (b)

Ship (a): single focus + a quiet momentum strip

Rationale. We recommend (a) — a single-focus surface with one quiet momentum strip — over (b), the light command-centre. The dashboard's whole promise is orientation in five seconds, and orientation is a function of hierarchy, not information: the instant a second panel carries equal visual weight, the eye has to choose where to land and the "one next move" stops being obvious — which is exactly the busyness the density pass just removed. (a) keeps a single dominant object (the hero), and demotes momentum, the ranked queue, and blockers into calm, glanceable support that a founder reads only after they've seen the move. It reads as calm and true to the surface's job. The desktop "empty" complaint is real but it is a hierarchy problem, not a quantity problem — we solve it by letting the hero grow to fill the width (§05), not by adding widgets. What (b) costs: it uses the real estate more literally and surfaces more at once, but re-introduces four competing panels, pushes orientation past five seconds, and drifts the dashboard toward being a second roadmap. We keep (b)'s good idea — momentum and blockers are worth showing — but as subordinate context, not co-equal cards.

Default lean confirmed. Focus first, supporting context second. The momentum strip is the one piece of (b) we bring across, deliberately down-weighted (thin strip, no card chrome, muted type). If product wants (b) later for a "power" density mode, it's a settings toggle over the same data — not the default.

05 · DESKTOP — HOW THE HERO EARNS THE WIDTH

Answering the empty-real-estate complaint

Desktop does not get more cards. It gets a bigger hero. Two-column body: the move dominates the left (~1.35fr), the support rail (momentum / then this / waiting) sits calm on the right (~1fr). The founder still lands on one thing; the rail is glance-context.

layoutgrid-template-columns: 1.35fr 1fr, gap 34px, body padding 38–44px
hero headlineDM Serif Display 38px (vs 24px mobile), max 16ch — the serif carries the width
hero supportInter 16px, max 44ch · theme tag 13px · Start button 15px
support railmomentum rows, 2 shortlist tasks, 1 waiting card — same components, no new ones
Same components, two sizes. Nothing on desktop exists that isn't on mobile. The width is filled by scale and whitespace, not by inventing widgets — which keeps a single source of truth and keeps "orient in 5s" intact on both.

06 · DEPENDENCIES — SEQUENCE THIS

What needs unbuilt work

Momentum strip needs completion data. "N moved since Monday" and the recently-completed rows require the work loop's completion events (R-WP-C, the create/date/complete/delete/done lane). Until that ships there are no completions to show. Sequence: build the hero + then-this + waiting on now (they read the existing ranked queue); land the momentum strip after R-WP-C so it has real signal. Ship-safe fallback until then: the strip collapses when there are zero completions in the window — do not show "0 moved" or a placeholder.
Hero data derivation is ticketed elsewhere. The highest-value-move logic (first task of the focus theme, advancing on completion) is owned by decide-first-highest-value-ticket.md. This brief specs presentation only. Build consumes that ticket's output; don't re-derive here.
Focus theme comes from Roadmap. The "Focus theme · {name}" tag reads the roadmap's current focus theme. No new pipeline — reuse the existing theme reference the Roadmap tab already owns.

09 · OPEN DECISIONS TO LOCK

Confirm before ticketing

  • 1Direction (a) vs (b). Lock (a) — single focus + quiet momentum — as the default? Recommend: yes. (b) available later as an opt-in density mode over the same data.
  • 2Momentum window. "Since Monday" (week-anchored) or "since you were last here" (session-anchored)? Recommend: since last visit, labelled with the actual day — truer to "what changed while you were away."
  • 3Momentum in the empty case. Confirm the strip collapses at zero completions (no "0 moved"). Recommend: collapse — and until R-WP-C ships it's simply absent.
  • 4Shortlist depth. Show top 2 or top 3 of the ranked queue on the dashboard? Recommend: 2 on mobile, 2 on desktop — more turns "then this" into a list and pulls focus off the hero.
  • 5Hero tap target. Whole card routes, or only the Start button? Recommend: whole card routes; Start is the visible affordance.
