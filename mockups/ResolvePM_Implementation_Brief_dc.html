Developer handoff · Alpha · consolidated build + motion brief

ResolvePM — implementation brief

The single source of truth. Every screen, every interactive element and every animation in the delivered mockups — what each one is, what it does, where it leads, and how it moves (trigger, motion, duration, easing). Built to be audited element by element against the mockups.

Absorbs the former Gate 1 / Floor Refusal brief and the standalone Motion Spec. Motion values below are transcribed verbatim from the mockups and Resolve Flow Spec (Surfaces A–I) and can be followed as written. Brand system is locked — colours, type (DM Serif Display for one headline per screen; Inter elsewhere), 10px/6px radii, sentence-case labels are baked into every mockup. Do not introduce new styles.

How to read this

Each screen carries up to three blocks. Behaviour — state logic and copy notes. Elements & actions — a row per control, with what it is and where it leads (terracotta arrow). Motion — a row per scripted animation, with its trigger (small caps), what moves, and a mono timing badge (duration · easing). Use the two audit blocks to confirm every affordance and every moving part in the mockup has a defined behaviour. Decisions taken where a mockup and the motion spec differed (Roadmap, Work, Knowledge) are recorded inline in green Decision boxes.

Read this first — global conventions

  • Two surfaces, one system. The intake flow (pre-auth) is a desktop-width web experience (~1180px) with a 4-step left stepper and a dark topbar carrying an amber progress bar (25/50/75/88/100%) + "Reset" pill. The app (post-auth) is mobile-first for Alpha (390px), desktop to follow. Same tokens throughout.
  • Light Surface is the base. Dark Ink is reserved for one dominant moment per screen (win card, do-first card, welcome veil). Never a dark theme throughout. Exactly one DM Serif element per screen.
  • App navigation is a fixed bottom tab bar (chosen: App Shell 1a) — locked order: Dashboard · Roadmap · Work · Team · Knowledge (align every mockup to this). During onboarding only Roadmap is unlocked; the rest are visible but locked (padlock badge) until the roadmap is confirmed (Global Bar · gn). Settings is not a tab.
  • Global orchestrator = a floating pill (chosen: Global Bar gb, contextual gc copy), docked above the tab bar on every tab once the app shell has revealed — not during the chrome-free build sequence. Prompt + suggestions are contextual to the tab; drives ask · find · navigate · capture · confirmed-create; opens into one sheet (gx). Supersedes the old "Search workflows · ⌘K" sidebar element (Global Bar ga is its descendant).
  • Loaders narrate. Every processing wait shows an amber spinner ring + a short checklist that ticks off stages (not a bare spinner). Loaders run once through in product; the mockups loop for preview.
  • First-run vs recurring. Grand one-time moments (bridge, OS assembly, Team intros) play only on first visit; every later open is the subtle version.
  • Persistence. The Dashboard "win for today" and the confirmed Roadmap are stored, stable state — not recomputed on load. Never show a "refresh" affordance.
  • The honesty thesis governs the Gate 1 halt (§7.5) and provisional theme marking (Part E): show the right direction, and mark what was inferred vs what the founder said.

Global motion tokens (shared across the app — Surfaces E–I)

Every app-side animation uses these four easings. Implement with WAAPI (element.animate, fill:'both'); staggered steps apply delay + (index × stagger) in DOM order.

--e-springcubic-bezier(.34,1.56,.64,1) — arrivals, expansions, sheets (slight overshoot)
--e-outcubic-bezier(.22,.61,.36,1) — decelerate-in reveals, restore
--e-stdcubic-bezier(.4,0,.2,1) — dims, press, tab colour
--e-incubic-bezier(.55,0,.85,.35) — exits, route-out
amber focusborder #C8A040 + box-shadow:0 0 0 3px rgba(200,160,64,.22)

Global bar → agent chat (E4, reused on every tab): backdrop dim 240ms; chat sheet (80% height, rounded top) rises translateY(100%)→0 460ms · spring delay 40ms; sheet rows fade up 300ms · out delay 300ms stagger 60ms. Only the resting caption differs per tab.

Part E · Provisional theme marking & the honesty thesis

Why the Gate 1 halt (§7.5) has no escape hatch, and why some roadmap themes are marked.

Sign-in · verify→Gate 1 check→passes: Roadmap cards → Reveal
  • Two gates considered; only one halts. Gate 1 (no real outcome) halts — nothing to build toward. Gate 2 (no lever) no longer halts: if we know the outcome and the current state, working out the path between them is the product.
  • Gate 2 failing is our failure, not theirs. Instead of halting we build the roadmap and mark inferred themes provisional — honest about what we inferred; Beta offers to sharpen.
  • Why no escape hatch on Gate 1. A hatch made sense only while Gate 2 halted (known outcome → honest inference toward a target). Gate 1 means no outcome, so a "provisional roadmap anyway" would be aimed at nothing — fabrication. A hatch would also kill the halt in practice (one click beats typing a sentence).
  • The marker is the smallest expression of the thesis. ChatGPT hides uncertainty behind confident prose; Resolve shows it. (The compass / map motif is out of scope for Alpha — the marker is the provisional chip + why line.)
